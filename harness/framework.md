## 2. 個別定義シートの書き方(WORKING3)

1文の骨格は「INPUT → DO → OUTPUT」。書く順序も INPUT → DO → OUTPUT → トリガー → メモ。

| 項目 | 内容 | 記入のコツ |
|---|---|---|
| INPUT | 処理に必要な情報・資材 | 「◯◯システムの△△データ」など具体名で |
| DO | 処理内容 | 動詞+目的語で簡潔に(例:「請求書を作成する」) |
| OUTPUT | 処理完了状態 | そのステップの「ゴール」を明記 |
| トリガー | 着手条件 | 「毎月末」「納品完了日」など着手タイミングが特定できる形で |
| メモ | 補足 | 例外処理・判断ポイントなど、他メンバーにも有用な情報 |

最初から精緻に書こうとしない。WORKING4(前後工程すり合わせ)で他担当者とすり合わせて精度を上げる。

## 3. 前後工程のすり合わせ(WORKING4)

- **自工程完結(JKK)**: 自分の工程で業務を完結させる意識を持ちつつ、前後との整合を必ず確認する。
- **PUSH型 / PULL型**: PUSH=「終わったから次へ」で前工程都合の受け渡し。PULL=後工程が必要な状態・タイミングを前工程に伝え、それに応じて前工程が渡す。ムダの削減にはPULL型の発想が有効。
- 確認する3観点:
  1. INPUT/OUTPUTの整合性(自分のOUTPUTは後工程のINPUTとして機能するか)
  2. タイミング/トリガーの整合性(前工程の終了と自工程の開始にズレはないか)
  3. 目的と成果物の整合性(その成果物は後工程にとって本当に有益か)

## 4. ムダ時間の分類(図表3.1)

McKinsey調査によれば、ホワイトカラーの業務時間のうち約39%が情報検索、26%が社内コミュニケーションに費やされ、実質的な業務遂行は約6割にとどまる。課題の分類には以下を使う。

| 分類 | 内容 | 例 |
|---|---|---|
| 探す時間 | 情報・ファイル・担当者の所在を探す | 「あのファイルどこだっけ」 |
| 確認する時間 | 内容・状態の正しさを都度確認する | システムとリストの手動突合 |
| 問い合わせる時間 | 他者への照会・回答待ち | 「この件、誰に聞けばいい?」 |
| 判断待ち時間 | 承認・意思決定待ち | 上長承認待ちで滞留 |

`templates/05_課題一覧.md` ではこの4分類のいずれかを課題に必ずタグ付けする。月間ムダ時間 =
所要分/回 × 頻度(回/月) ÷ 60 で算出し、効果予測の基礎数値とする。

## 5. 優先順位マトリクス(WORKING7)

軸: **効果(横軸)× 実行しやすさ(縦軸)**、各0〜10で評価。

| 象限 | 位置 | 意味 |
|---|---|---|
| 最優先 | 高効果 × 実行しやすい | まず着手する |
| 中長期 | 高効果 × 実行しにくい | 投資判断のうえ計画的に進める |
| 低優先 | 低効果 × 実行しやすい | 手隙のタイミングで対応 |
| 省略検討 | 低効果 × 実行しにくい | やらない判断も選択肢 |

「実行しやすさ」は承認の少なさ・必要条件の少なさ・システム改修の要否などから判断する。

## 6. TO-BEのAI活用パターン(4類型)

書籍の「人間とシステムの最適な組み合わせ」「後工程からの逆算」の考え方をもとに、本ハーネスでは
改善案を難易度・自律性で4段階に整理する。1つの業務に対して複数パターンを並べて提示し、
状況(予算・システム連携可否・データの定型度)に応じて選べるようにする。

| パターン | 概要 | 向いている業務 | 導入負荷 |
|---|---|---|---|
| A. 業務簡素化 | 様式統一・ルール変更・チェックリスト化(AI不要) | ムダの原因が「ばらつき」にある業務 | 小 |
| B. ルールベース自動化 | RPA・ワークフローツールによる定型処理の自動化 | 判断を伴わない、ルールが明確な定型業務 | 中 |
| C. 生成AI活用 | 文書生成・要約・分類・一次回答案の作成などをAIが支援 | 非定型入力(自由記述メール等)を含み、判断を伴う業務 | 中 |
| D. AIエージェント型 | 複数システムを横断し複数ステップを自律実行、例外のみ人が確認 | 複雑・多工程で、後工程まで一気通貫にできる業務 | 大 |

パターンが進むほど効果は大きくなりやすいが、実行しやすさ(前提条件の重さ)は下がる傾向にある
ため、優先順位マトリクス上では右下がりの分布になりやすい。これを鵜呑みにせず、対象業務の
実データで効果・実行しやすさを個別に見積もること。

## 7. 効果予測の算出ロジック

- **定量(時間)**: `Σ(該当課題の月間ムダ時間 × パターン別の想定削減率)`
  削減率の目安 — A:20〜30% / B:50〜70% / C:50〜65%(判断系は誤り率次第で変動) / D:70〜85%
- **定量(リードタイム/エラー率)**: 現状のボトルネック工程(トリガー〜OUTPUTの間隔が長い、または
  ムダ時間タグが集中している工程)を基準に、自動化後の想定所要時間から見積もる。
- **定性**: 属人化の解消・心理的負荷の軽減・後工程への波及効果など、金額換算しにくいが重要な効果を
  必ず併記する(書籍の「業務のスリム化は削ることではなく、本質に立ち返ること」という視点)。

数値は「見込み」であることを明記し、WORKING7の対話(なぜその評価にしたか)を通じて精度を上げる。
