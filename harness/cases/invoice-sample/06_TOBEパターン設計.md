# 06. TO-BEパターン設計(4-4「理想の業務プロセスを設計する」+ AI活用提案)

---

## パターンA. 業務簡素化

- **タグライン**: 納品連絡の様式統一とチェックリスト化で手戻りを解消
- **対応する課題ID**: I1, I2
- **前提条件**: 定型フォーム・チェックリストの合意形成、営業への周知
- **リスク・留意点**: 定着までの移行期間に運用ブレが生じやすい

### 変更後の業務フロー

| ID | ステップ名 | 担当者 | INPUT | OUTPUT | トリガー |
|---|---|---|---|---|---|
| B1 | 納品完了報告(定型フォーム) | 営業 | 納品完了の連絡 | 定型フォーム | 納品完了時 |
| B2 | 納品データ確認(チェックリスト) | 経理 | 定型フォーム | 確認済みリスト | 月末 |
| B3 | 請求書作成 | 経理 | 確認済みリスト | 請求書(PDF) | 確認完了後 |
| B4 | 上長承認 | 経理 | 請求書(PDF) | 承認済み請求書 | 作成完了後 |
| B5 | 請求書受領・照合 | 顧客 | 承認済み請求書 | 受領確認 | 送付後 |

### 効果予測

| 指標 | 値 | 根拠 |
|---|---|---|
| 月間削減時間 | 5h/月 | I1+I2の月間ムダ時間(14.6h)× 想定削減率約30% |
| リードタイム変化 | 変化なし | |
| エラー率変化 | -20% | 突合ミスの減少 |
| 定性効果 | フォーマット統一による属人化の低減。追加投資ゼロで着手可能 | |

## パターンB. ルールベース自動化

- **タグライン**: RPAで突合・請求書生成を自動処理
- **対応する課題ID**: I1, I2
- **前提条件**: 販売管理システムとのAPI/CSV連携、RPAツール導入・シナリオ開発、例外処理フローの設計
- **リスク・留意点**: システム改修コストが発生。例外ケースの網羅性を継続メンテする必要

### 変更後の業務フロー

| ID | ステップ名 | 担当者 | INPUT | OUTPUT | トリガー |
|---|---|---|---|---|---|
| C1 | 納品完了報告(システム連携) | 営業 | 納品完了の連絡 | 納品データ(自動登録) | 納品完了時 |
| C2 | RPAによる自動突合 | 経理 | 納品データ・販売管理システム | 請求対象リスト | 毎日夜間バッチ |
| C3 | RPAによる請求書自動生成 | 経理 | 請求対象リスト | 請求書(PDF) | 突合完了後 |
| C4 | 例外分のみ人による確認 | 経理 | 不一致リスト | 確定リスト | 突合エラー時のみ |
| C5 | 上長承認 | 経理 | 請求書(PDF) | 承認済み請求書 | 作成完了後 |
| C6 | 請求書受領・照合 | 顧客 | 承認済み請求書 | 受領確認 | 送付後 |

### 効果予測

| 指標 | 値 | 根拠 |
|---|---|---|
| 月間削減時間 | 14h/月 | I1+I2の想定削減率約65%相当 |
| リードタイム変化 | -2営業日 | |
| エラー率変化 | -60% | |
| 定性効果 | 突合・生成の完全自動化で経理の定型作業を圧縮。例外対応に人的リソースを再配分できる | |

## パターンC. 生成AI活用

- **タグライン**: メール・チャットの内容を生成AIが読み取り、突合と問い合わせ対応を支援
- **対応する課題ID**: I1, I2, I3, I4
- **前提条件**: 社内データでのプロンプト・抽出精度検証、機密情報の取り扱いルール整備
- **リスク・留意点**: 抽出誤りのチェック体制が必要。生成物の最終責任は人が持つ運用設計が必須

### 変更後の業務フロー

| ID | ステップ名 | 担当者 | INPUT | OUTPUT | トリガー |
|---|---|---|---|---|---|
| D1 | 納品完了報告(自由記述可) | 営業 | 納品完了の連絡 | メール/チャット | 納品完了時 |
| D2 | 生成AIによる情報抽出・突合 | 経理 | メール/チャット・販売管理システム | 請求対象リスト(要確認フラグ付き) | 受信都度 |
| D3 | 生成AIによる不一致の一次回答案作成 | 経理 | 不一致リスト | 問い合わせ文案 | 不一致検知時 |
| D4 | 請求書ドラフト生成・人によるレビュー | 経理 | 請求対象リスト | 請求書(PDF) | 突合完了後 |
| D5 | 上長承認(AI要約付き) | 経理 | 請求書(PDF)・変更点要約 | 承認済み請求書 | 作成完了後 |
| D6 | 請求書受領・照合 | 顧客 | 承認済み請求書 | 受領確認 | 送付後 |

### 効果予測

| 指標 | 値 | 根拠 |
|---|---|---|
| 月間削減時間 | 18h/月 | I1〜I4すべてに効くため、想定削減率約80%相当 |
| リードタイム変化 | -2営業日 | |
| エラー率変化 | -50% | |
| 定性効果 | 非定型な報告(自由記述メール等)にも対応できる柔軟性。問い合わせ文案の自動生成で営業とのやり取りが短縮。承認者は要約を確認するだけで済み負荷軽減 | |

## パターンD. AIエージェント型

- **タグライン**: 受注〜請求〜入金確認までを横断的に自律実行するエージェントを導入
- **対応する課題ID**: I1, I2, I3, I4
- **前提条件**: 複数システム(販売管理・請求・入金)のAPI連携基盤、承認閾値・エスカレーションルールの設計、監査ログ・ガバナンス体制の整備
- **リスク・留意点**: 導入・運用コストが大きい。初期は監督コストが高く信頼醸成に時間を要する。システム障害時の代替手順が必要

### 変更後の業務フロー

| ID | ステップ名 | 担当者 | INPUT | OUTPUT | トリガー |
|---|---|---|---|---|---|
| E1 | 納品完了報告(システム連携) | 営業 | 納品完了の連絡 | 納品データ | 納品完了時 |
| E2 | AIエージェントが突合〜請求書発行まで自律実行 | 経理 | 納品データ・販売管理・請求システム | 発行済み請求書 | 納品データ登録時 |
| E3 | 例外・高額案件のみ人が最終承認 | 経理 | 発行前請求書(閾値超過分) | 承認済み請求書 | 閾値超過時のみ |
| E4 | 請求書受領・照合 | 顧客 | 承認済み請求書 | 受領確認 | 送付後 |
| E5 | AIエージェントが入金消込を自動実施 | 経理 | 入金データ | 消込済み記録 | 入金確認時 |

### 効果予測

| 指標 | 値 | 根拠 |
|---|---|---|
| 月間削減時間 | 28h/月 | 全課題を包含し、入金消込まで自動化するため想定削減率約85%相当以上 |
| リードタイム変化 | -4営業日 | |
| エラー率変化 | -75% | |
| 定性効果 | 請求〜消込までの一気通貫自動化。経理担当は例外対応・監督業務にシフト。月次決算の早期化に寄与 | |
